# ROADMAP — LoL 1v1 팬게임

각 하위 단계는 하나씩 구현하고, "완료 기준"을 직접 확인한 뒤 체크한다.
설계 원칙은 `CLAUDE.md` 참고. 처음에는 **챔피언 1명 미러전**으로 끝까지 완성하고, 챔피언 추가는 마지막에 한다.

---

## Phase 1. 프로젝트 기초 공사

- [x] **1-1. 모노레포 구성**
  - npm workspaces로 `client/`, `server/`, `shared/` 구성
  - client: Vite, server: Express + Socket.io, shared: 다른 두 곳에서 import 가능하게 설정
  - 루트 `npm run dev` 하나로 클라이언트와 서버 동시 실행
  - 완료 기준: `npm run dev` 실행 시 에러 없이 둘 다 뜬다

- [x] **1-2. 서버 연결 확인**
  - 브라우저 접속 시 소켓 연결
  - 완료 기준: 서버 콘솔에 `Connected: [소켓ID]`, 브라우저 콘솔에 `Connected to server`

- [x] **1-3. shared 연결 확인**
  - `shared/constants.js`의 상수를 클라이언트와 서버 양쪽에서 불러와 출력
  - 완료 기준: 양쪽 콘솔에 같은 값이 찍힌다

---

## Phase 2. 로컬 렌더링과 이동 (네트워크 없음, 구조는 서버용으로)

이 단계에서는 `shared/`의 로직을 브라우저에서 직접 실행한다. Phase 4에서 같은 로직을 서버로 옮긴다.

- [x] **2-1. 게임 상태 구조와 게임 루프**
  - `shared/`에 게임 상태 구조(플레이어 목록, 투사체 목록, 맵 크기) 정의
  - `update(state, inputs, dt)` 함수 뼈대 작성
  - 클라이언트에 고정 간격 루프(30Hz 로직) + requestAnimationFrame 렌더링
  - 완료 기준: 화면에 아무것도 없어도 루프가 에러 없이 돈다

- [x] **2-2. 아레나 렌더링**
  - 탑뷰 아레나(바닥, 외곽 벽, 양쪽 진영 시작 지점) 그리기
  - 맵이 화면보다 크면 내 캐릭터를 따라가는 카메라
  - 완료 기준: 아레나가 보이고 창 크기를 바꿔도 깨지지 않는다

- [x] **2-3. 캐릭터와 우클릭 이동**
  - 원 형태의 임시 캐릭터
  - 우클릭 지점으로 이동 (브라우저 우클릭 메뉴 차단), 도착하면 정지, 벽 통과 불가
  - 이동 로직은 `shared/`, 입력 수집은 `client/`
  - 완료 기준: 우클릭한 곳까지 떨림 없이 이동하고 멈춘다

- [x] **2-4. 닉네임과 체력바**
  - 캐릭터 머리 위에 닉네임, 체력바, 마나바
  - 완료 기준: 테스트용 키로 체력을 깎으면 바가 줄어든다

- [ ] **2-5. 연습용 허수아비**
  - 움직이지 않는 두 번째 캐릭터 배치 (Phase 3 전투 테스트용)

## Phase 3. 전투 시스템 (로직은 전부 shared/)

- [ ] **3-1. 챔피언 데이터 파일**
  - `shared/champions.js`에 챔피언 1명 정의 (체력, 마나, 이동속도, 평타 사거리, Q/W/E/R)
  - 스킬 형태: 직선 투사체 / 원형 범위 / 대시 / 자기 강화 중에서 선택

- [ ] **3-2. 기본 공격**
  - 사거리 안의 적을 우클릭하면 평타 (원거리면 투사체 발사, 공격 속도 적용)
  - 원-원 충돌로 적중 판정
  - 완료 기준: 허수아비를 때리면 체력이 깎인다

- [ ] **3-3. 스킬 Q/W/E/R**
  - 스킬 키를 누르면 범위 표시, 클릭하거나 키를 떼면 마우스 방향으로 시전
  - 마나 소모, 쿨타임 적용 (마나 부족·쿨타임 중이면 시전 불가)
  - 완료 기준: 네 스킬이 데이터대로 동작하고 쿨타임이 화면에 숫자로 보인다

- [ ] **3-4. 사망과 리스폰**
  - 체력 0이면 사망 → 일정 시간 후 시작 지점에서 부활
  - 마나·체력 자연 회복
  - 완료 기준: 허수아비를 처치하면 사라졌다가 부활한다

---

## Phase 4. 온라인 멀티플레이 (서버 권위 방식)

- [ ] **4-1. 매치룸과 플레이어 관리**
  - 접속 시 고유 ID 발급, 로비 대기열에 추가
  - 2명이 모이면 매치룸 생성 후 둘을 그 방에 배정
  - 접속 종료 처리 (상대에게 알림)
  - 완료 기준: 브라우저 두 개로 접속하면 같은 방에 들어간다

- [ ] **4-2. 서버 게임 루프와 입력 전송**
  - 게임 루프를 서버로 이동 (방마다 30Hz로 `shared/`의 `update` 실행)
  - 클라이언트는 입력만 전송 (`move`, `attack`, `cast`)
  - 서버는 상태를 두 플레이어에게 브로드캐스트
  - 완료 기준: 한쪽 창에서 이동하면 다른 창에서도 움직인다

- [ ] **4-3. 클라이언트 보간**
  - 받은 상태 두 개 사이를 보간해서 그리기 (약 100ms 뒤를 렌더링)
  - 내 캐릭터 이동은 클릭 즉시 반응하도록 예측 처리 (선택)
  - 완료 기준: 상대 캐릭터가 끊기지 않고 부드럽게 움직인다

- [ ] **4-4. 전투 동기화**
  - 평타·스킬·투사체·데미지·사망·리스폰을 서버 판정으로 처리
  - 완료 기준: 두 화면에서 체력과 적중 결과가 항상 같다

- [ ] **4-5. 지연 테스트**
  - 서버에 인위적 지연(100~150ms) 옵션 추가해서 랙 상황 확인
  - 완료 기준: 지연을 줘도 판정이 어긋나지 않고 플레이 가능하다

## Phase 5. 게임 규칙과 승패

- [ ] **5-1. 로비 화면**
  - 닉네임 입력 → 매칭 대기 화면 → 상대를 찾으면 카운트다운 후 시작

- [ ] **5-2. 승리 조건**
  - 먼저 3킬 달성 시 승리 (넥서스 파괴 모드는 나중에 선택 사항으로)
  - 화면 상단에 킬 스코어 표시
  - 완료 기준: 3킬 시 양쪽에 Victory / Defeat 화면이 뜬다

- [ ] **5-3. 재매치와 로비 복귀**
  - 종료 화면에서 재대결(둘 다 동의 시) 또는 로비로 돌아가기
  - 게임 도중 상대가 나가면 남은 사람 승리 처리

## Phase 7. 배포와 실전 테스트

- [ ] **7-1. 배포**
  - Express 서버가 빌드된 클라이언트까지 함께 서빙하도록 구성 → Render(또는 Railway) 한 곳에 배포
  - 환경 변수로 포트 설정, 프로덕션 빌드 스크립트 추가
  - 참고: Render 무료 플랜은 접속이 없으면 잠들어서 첫 접속이 느릴 수 있음
  - 완료 기준: 배포 주소로 두 기기에서 접속해 대전이 된다

- [ ] **7-2. 친구와 실전 테스트**
  - 화면에 핑(ms) 표시
  - 서로 다른 네트워크에서 대전하며 버그 목록 작성 → 수정
